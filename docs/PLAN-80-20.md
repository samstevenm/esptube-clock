# The 80/20 plan — stable enough to live with, easy to extend

*2026-09-17.* What makes this clock usable every day and safe to build on, ranked by impact per hour.
✅ = shipped today · 🔜 = next · ⬜ = later.

## 1. One owner of the glass, always (✅)
Every path that draws — device faces, nixie messages, the helper's pushes, 📹 Live, the bridge, the scene
cycle, the animation pusher — now yields to a **master clear** (🧹 in the helper, `POST /tubes/clear`,
shell `clear`): it stops the message/countdown, a running sweep and the LED effect, blanks every panel and
glow, and the helper stops its own stream, the bridge, the cycle and the pusher first. Nothing repaints a
cleared clock until something is asked for. The **idle timer** (`/config/idle`, default 30 min, shell
`idle N`, 0 = never) hands pushed content back to the clock face when nobody refreshes it — a stale frame
never sticks overnight.

## 2. It works with no network, and recovers on its own (✅)
Roaming over 8 saved networks, blind-join of the last good one at boot, recovery hotspot with captive
portal, the DS1302 keeping time, a UART rate watchdog, one-shot boot rates, the cable as a full transport
(control + pixels) at the best rate the chip does (460800 here). Verified with the clock off-network and
with the Mac→clock wire physically dead.

## 3. Parity: every control reachable from every surface (✅)
REST · shell over USB · on-device page · the helper (file://, or served by the clock at `/helper` as a
phone app) all expose faces, messages, LEDs, brightness, time, WiFi, clear. Shell gained `clear`, `rgb`,
`text`, `idle`; the helper routes all of them over the cable when the network is down. Gaps that remain:
per-tube *images* over the cable use PAL4x2 frames (fine); the on-device page has no cast/look (use
`/helper`).

## 4. Content that composes (✅ / 🔜)
🎭 **Cast**: drag any face onto any tube (or a slot), load a whole family, mix families, persisted, ships in
backups. 🎨 **Look**: background (colour · gradient · glow · the animation studio's frame) + brightness /
contrast / saturation / hue with presets, for every Live source. 🔜 Characters rendered with **alpha** so
backgrounds show through (in progress); 🔜 save a cast + look as a 🎭 scene so the cycle can call it up.

## 5. Guard rails (✅ / 🔜)
Low-heap guard refuses new stream clients under 40 KB free; LRU slot eviction; the task watchdog; reset
reasons and a truthful build stamp in `/status`; REST smoke covers clear / wifi / time / idle / hosted
helper. 🔜 a `test/serial-smoke.py` that opens the cable, checks `help`, `status`, `clear` and one PAL4x2
frame end to end (needs the port free); 🔜 a nightly `rest-smoke` from the Mac with a one-line report.

## 6. Extend without fear (🔜)
The seams to build on: `Net` (network policy), `Rtc`, `Esp1` (frames in), `Shell` (text in), `Control`
(what the glass shows), `Api` (HTTP glue) — each a namespace with a small header. Add a face: a preset in
`Control`. Add a source: a `frame source` in the helper's Live panel or a `Source` in the bridge. Add a
transport: implement the four `Link` calls. Keep `docs/ESP1-PROTOCOL.md` the single wire-format truth.

## Not doing (on purpose)
DMA for the panel bus (crashed the fork; 80 MHz SPI gained nothing), UDP frames (lossy), BT Classic
(doesn't fit), persisting a fast UART rate (stranded the shell). Bluetooth LE is measured and shelved
(`GUIDE.md` §13).
